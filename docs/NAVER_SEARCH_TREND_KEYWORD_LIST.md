## 1. 키워드 설정 3대 핵심 원칙

### ① 브랜드 고유명 검색 결손(Zero Index) 방지: 유의어 번들링
- '테트리스 브레드', '마틸다 초코케이크' 같은 독창적 브랜드 고유명은 네이버 일간 검색량이 0이거나 매우 적습니다.
- 검색량이 0이면 지수가 나오지 않고, 단 1~2건 검색에 변동률이 `+500%`로 튀는 노이즈가 발생합니다.
- 따라서 네이버 API의 `keywords` 배열을 활용하여 **[대표 카테고리 일반명 + 브랜드 고유명 + 웰니스 특화 키워드(글루텐프리/비건/무설탕)]**를 하나의 주제어로 묶는 **'유의어 번들링(Grouping)'**을 적용했습니다.

### ② 절대 검색량 격차 보정: 개별 품목 14일 이동평균 모멘텀
- 대중적인 '휘낭시에'(일 수만 건)와 '비건 머핀'(일 수백 건)을 한 바구니에 넣고 상대 비교하면, 비주류 빵은 항상 지수가 1~2점에 머물러 가격이 영원히 움직이지 않습니다.
- 타 제품과의 절대량 비교가 아닌, **"해당 빵이 자기 자신의 최근 14일 평균 검색량($\mu_{14}$) 대비 오늘 얼마나 더 튀었는가(Momentum, $M$)"**를 측정합니다.

### ③ 네이버 API 제한 대응: 5개 그룹 분할 호출
- 네이버 데이터랩 API는 1회 호출 시 최대 5개 `keywordGroups`까지만 전달할 수 있습니다.
- 따라서 10종 상품을 **[Tier 1 소형 디저트/식사빵 5종]**과 **[Tier 2~3 케이크/식빵/생지 5종]**으로 2회 분할 호출하여 수집합니다.

## 4. 검색 지수의 빵 시세 환산 공식 및 예외 방어

### 1) 당일 검색 모멘텀($M$) 산출
$$\mu_{14} = \frac{1}{14} \sum_{i=1}^{14} T_i \quad \text{(14일 이동평균 지수)}$$
$$M = \frac{T_{\text{today}} - \mu_{14}}{\max(\mu_{14}, 1.0)}$$
> **예외 방어:** 분모에 `max(μ_14, 1.0)`을 두어 과거 검색량이 0에 수렴할 때 발생하는 `DivisionByZero(NaN)` 에러를 원천 차단합니다.

### 2) 민감도 계수($\alpha$) 적용 및 트렌드 한도 클램핑
$$\Delta\text{Trend} = \max\left(-5.0\%, \min\left(+5.0\%, M \times \alpha\right)\right) \quad (\alpha = 0.0833)$$
- 검색량이 `+60%` 이상 폭증하면 트렌드 상한인 **`+5.0%` (인기 프리미엄)** 도달
- 검색량이 `-60%` 이상 감소하면 트렌드 하한인 **`-5.0%` (깜짝 알뜰 특가)** 도달

### 3) 거시 환율($\Delta\text{FX}$) 결합 및 3단계 차등 캡 적용
$$\text{RawRate} = \Delta\text{Trend} + \Delta\text{FX}$$
$$\text{FinalRate} = \max(-\text{TierCap}, \min(+\text{TierCap}, \text{RawRate}))$$

* **Tier 1 (1만원 미만 5종):** $\text{Cap} = \pm10\%$ (체감 재미 극대화)
* **Tier 2 (1만~2만원 3종):** $\text{Cap} = \pm7\%$ (부담 없는 일상 디저트)
* **Tier 3 (2만원 이상 2종):** $\text{Cap} = \pm5\%$ (마진 리스크 철통 방어)

## 5. 시스템 아키텍처 및 일일 배치 운영 룰

```text
[매일 아침 08:30 (배치 크론 실행)]
  ├── 1. 네이버 DataLab API 호출 ➔ 10종 빵 D-1 검색지수(0~100) 수집
  ├── 2. 한국은행 ECOS API 호출 ➔ USD/KRW 전일 종가 환율 수집
  └── 3. BREAD-DAQ 가격 엔진 연동 ➔ 3단계 차등 캡 적용 및 당일 시세 확정 DB 적재
                                    ↓
[매일 아침 09:00 (정규장 개장)]
  └── 4. 자사몰/모바일앱에 '오늘의 시세' 오픈 ➔ 카카오 알림톡/앱푸시 발송
```

- **D-1 시차 운영 룰:** 네이버 데이터랩 API는 실시간이 아닌 '어제(D-1) 23:59까지 집계된 일간 데이터'를 제공하므로, 서비스 상에 **"매일 아침 09:00, 어제 전 국민이 가장 많이 찾은 검색 트렌드를 집계해 오늘의 시세로 개장합니다"**라는 주식 시장식 운영 룰을 확립하여 고객 인지 괴리를 해소합니다.
