## 1. 제품 개요

MAKJI STOCK은 **검색트렌드**와 **환율**을 반영해 매일 달라지는 빵값을 보여주는 서비스다. 사용자는 MAKJI STOCK에서 오늘 빵값을 확인하고, 구매할 상품을 선택하면 막지 자사몰(`makji.kr`, 카페24)로 이동한다. 두 사이트는 별도로 운영하며, 실제 주문·결제는 자사몰에서만 진행한다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | MAKJI STOCK |
| 타깃 사용자 | 매일 달라지는 빵 시세와 혜택을 확인하며, 단순 구매를 넘어 새로운 구매 경험을 즐기는 온라인 베이커리 소비자 |
| 핵심 가치 | 매일 새로운 가격을 확인하고 원하는 빵의 구매 시점을 판단하는 경험 |
| 핵심 메시지 | 매일 오전 9시, 오늘의 빵값이 열립니다 |
| 대표 체감 수치 | 4,500원 빵 기준 하루 평균 약 217원 변동(91일 백테스트, 참고용 — 화면에 산식·근거로 노출하지 않음) |

**핵심 이용 경험:** 오늘 빵값 확인 → 상품 비교 → 막지 자사몰에서 구매<br>
**추가 참여 경험:** 내일 가격 예측 → 다음 날 결과 확인 → 성공 시 할인 쿠폰 → 가격 하락·지정가 이메일 알림

가격 할인 자체가 목적이 아니라, 오늘의 가격을 확인하는 행동이 상품 탐색과 재방문으로 이어지게 하는 것이 핵심이다. 개인의 검색 한 번이 즉시 할인으로 바뀌는 구조가 아니며, 확정된 환율 데이터와 상품별 검색 관심도를 정해진 산식으로 반영한다.

## 2. 배경과 문제 정의

**기업 RFP 요구:** 외부 시장 데이터를 식품 구매 경험에 연결해 상품 관심·재방문·구매 전환을 유도하고, 메타 광고용 이벤트 페이지·SNS 홍보 소재로 신규 고객을 자사몰 구매로 연결한다.

**현재의 한계**

- 고정된 가격과 상품 진열은 다음 날 다시 확인할 새로운 정보가 적다.
- 광고 유입 이후 둘러볼 콘텐츠와 재방문 장치가 부족하다.
- 가격 확인과 실제 구매가 서로 다른 서비스에서 진행되므로 이동 맥락을 명확히 알려야 한다.

**기회:** "오늘 빵값은 얼마지?"라는 질문으로 가격 확인의 재미를 만들고, 이를 다음 방문과 구매 기회로 전환한다.

### 3.2 소비자가 기억할 경험

1. **아침 시세 확인:** "오늘 막지빵은 얼마일까?"라는 궁금증으로 접속
2. **오늘 가격 공개:** 오전 9시에 오늘 가격, 어제 대비 변동액, 가격이 달라진 이유를 확인
3. **재방문 습관:** 오늘과 내일의 가격을 비교하거나 예측 결과·알림을 확인하기 위해 다시 방문

SNS·광고 카피(소비자 언어, 산식 언급 금지): "오늘 막지빵, 어제보다 얼마나 달라졌을까요?" / "매일 오전 9시, 오늘의 빵값이 열립니다."

## 4. 목표(Goals)와 비목표(Non-goals)

### Goals

1. 방문 즉시 오늘 가격과 정가 대비 할인율을 이해하게 한다.
2. MVP 5종의 가격 흐름을 비교하고 상품 상세로 이동하게 한다.
3. 환율 할인과 검색수요 할인을 소비자 언어로 설명한다(산식·데이터 출처는 노출하지 않는다).
4. 선택 상품과 최종가격을 유지한 채 `makji.kr` 구매 페이지로 연결한다.
5. 내일 가격 예측과 가격 하락·지정가 알림으로 재방문을 습관화한다.

### Non-goals

- MAKJI STOCK 안에서 주문·결제를 처리하지 않는다.
- 로그인·회원가입 기능을 두지 않는다(7-3, 13장 참조).
- 운영 대시보드나 가격 산식·경보 기준을 소비자 화면에 노출하지 않는다.
- 구매 전환, 재방문 효과, 최적 할인율, 상품 수익성이 이미 검증되었다고 주장하지 않는다.
- '대란', '완판 행진' 같은 상한 돌파형 프레이밍을 사용하지 않는다(정찰제·투명성 원칙과 충돌).
- 38%p 상한을 넘는 이벤트성 할인은 만들지 않는다(23장).

## 5. 대상 사용자와 핵심 시나리오

주 사용자는 건강한 빵과 가격 혜택에 관심이 있고, 인스타그램·카카오톡 등 모바일 채널에서 막지를 처음 접하거나 재방문하는 소비자다. "오늘은 어떤 빵이 얼마나 내려갔을까?"를 빠르게 확인하고 구매 시점을 판단하려 한다.

**막지지수:** MVP 빵 5종의 정가 대비 가격 변화율을 평균한 값. 정가보다 평균 몇 % 낮아졌는지 표시한다.

### 8.1 HOME — FR-H01~H03

- **FR-H01 시장 브리핑:** 막지지수, 코스피·코스닥(연동 전 임시값 — 실제 지표처럼 오인되지 않도록 "연동 전" 표기를 명시한다)을 상단에 노출한다.
- **FR-H02 데일리 콘텐츠 진입:** 뉴스레터·오늘의 빵 운세·이벤트로 진입하는 카드를 제공한다.
- **FR-H03 뉴스레터 형식:** 제호 → 헤드라인 → 시장 지표 → 본문 → 시세 요약 → 데일리 콘텐츠 → 구독 순서로 구성한다(단순 시세 나열이 아니다).

### 8.2 Bread Market — FR-BM01~BM06

Bread Market의 상세 화면·API·데이터 모델은 `PRD_BREAD_MARKET_MVP.md` FR-01·FR-02, `SRS_BREAD_MARKET_MVP.md` 6~7장을 따른다. 이 PRD에서는 서비스 전체 관점의 요구사항만 정리한다.

- **FR-BM01:** MVP 5종을 주식시장의 종목 목록처럼 한 줄씩 나열하고, 상품 이미지·상품명·오늘 최종 할인율·오늘 가격·전일 대비 가격 변화를 표시한다.
- **FR-BM02:** 기본 정렬은 '많이 내린 순'이며 '가격 순', '이름 순'을 제공한다.
- **FR-BM03:** 상품 선택 시 상세 화면에서 할인 구성을 두 단계(환율 기반 기본 할인 → 검색수요 추가 할인)로 보여준다.
- **FR-BM04:** 검색수요 추가 할인은 별도 발급·적용하는 쿠폰이 아니라 가격 계산 시 자동 반영되는 값이다.
- **FR-BM05:** 화면 문구는 시스템 상한과 혼동되는 '최대 할인' 대신 '오늘 최종 할인'을 사용한다.
- **FR-BM06:** 구매 버튼은 '쿠폰 받기'가 아니라 '오늘 가격으로 구매하기' 또는 실제 금액을 넣은 '3,660원에 구매하기' 형식으로 표시한다.

### 8.3 상품 상세 — FR-PD01~PD02

- **FR-PD01:** 정가, 환율 기반 기본 할인·기본 할인가, 검색수요 추가 할인, 오늘 최종 할인율·최종 가격을 표시한다.
- **FR-PD02:** 자사몰 이동 전 선택 상품·최종가격·`makji.kr` 도메인을 재확인시킨다.

### 8.4 이벤트 — FR-EV01~EV05

- **FR-EV01 빵 자르기 게임:** 가볍게 참여하는 이벤트 콘텐츠.
- **FR-EV02 오늘의 빵 운세:** 매일 확인하는 데일리 콘텐츠.
- **FR-EV03 가격 하락·지정가 이메일 알림 신청:** 사용자가 관심 상품과(선택적으로) 희망 가격을 등록하면, 해당 상품 가격이 전일 대비 하락하거나 지정가 이하로 떨어졌을 때 이메일로 알린다. 로그인이 없으므로 이메일 주소만으로 등록하며, 수신 거부(옵트아웃) 링크를 모든 발송 메일에 포함한다.
- **FR-EV04 알림 조건 판정:** 09:00 가격 공개(Phase 1 배치)가 완료된 직후 알림 대상을 판정하고 발송한다. 동일 상품·동일 알림 조건에 대해 하루 1회만 발송한다.
- **FR-EV05 도감·씰 수집형 콘텐츠는 제외한다.** [[makji-stock-prototype]] 전제와 동일하게, 참여 여부는 이벤트 단위 완료 기록만 남기고 수집형 보상 체계는 만들지 않는다.

### 8.5 내일 가격 예측 / 결과·쿠폰 — FR-PR01~PR04

- **FR-PR01:** MVP 5종 중 무작위 1종을 예측 대상으로 선정한다.
- **FR-PR02:** 선택지는 '오른다 / 내린다'이며, 판정 기준은 해당 상품의 오늘 가격과 내일 가격 비교다.
- **FR-PR03:** 다음 날 가격이 확정되면 예측 성공/실패를 안내하고, 성공 시 할인 쿠폰을 제공한다.
- **FR-PR04:** 가격이 동일하거나 데이터 미갱신으로 판정이 불가능한 경우의 처리 규칙은 10-1 협의사항에서 확정한다(현재 미확정, 22장).

## 10. 가격 정책(확정)

가격 산식은 확정 사항이며, 향후 협의 대상으로 되돌리지 않는다.

```text
환율 하락률 = (D-2 확정 환율 − D-1 확정 환율) ÷ D-2 확정 환율 × 100   (0 이하이면 0)
원시 환율할인 = max(0, 환율 하락률 × 0.28 × 50)
환율할인 = min(28%p, 원시 환율할인)
검색수요 추가 할인 = min(10%p, 네이버 검색지수(0~100) × 0.1)   // 자동 반영, 별도 쿠폰 없음
캡 적용 전 원시 할인율 = 원시 환율할인 + 검색수요 추가 할인
총할인율 = min(38%p, 환율할인 + 검색수요 추가 할인)
오늘 가격 = 정가 × (1 − 총할인율 ÷ 100)
```

**원칙**

1. 환율이 하락한 경우에만 환율할인을 적용한다(상승·동일 시 0%p).
2. 전일 가격에 누적하지 않고 매일 정가에서 다시 계산한다.
3. 표시가격과 자사몰 실제 결제가격은 일치해야 한다(원 단위 처리 규칙은 자사몰 연동 정책에 맞춰 확정).
4. 외환시장 비영업일에는 마지막 영업일에 계산된 환율 하락률을 그대로 이월하되, 검색지수는 비영업일에도 갱신되므로 최종 가격은 달라질 수 있다.

**91일(2026.06.12~09.10, 달력 일수 기준) 백테스트 결과:** 중앙 할인율 12.0%p, 평균 12.5%p, 최대 30.9%p, 38%p 상한 도달 0일. 4,500원 기준 평균 할인금액 약 563원, 평균 일별 변동폭 약 217원(서로 다른 개념이므로 화면에서 구분 표시). 변동성 기여도는 환율 97%, 검색 3%. 이 결과는 산식의 동작 특성을 보여줄 뿐 구매 전환·재방문 효과·수익성을 증명하지 않는다.

상세 계산식·계산 예시는 `9_14_기획안_v2.md` 부록 B를 참조한다.

## 19. 검증 방법

- **기능 검증:** 수집 데이터·계산 결과·표시 가격을 비교하고, 연동 후 테스트몰의 실제 가격까지 대조한다.

- **운영 검증:** 다음 날 판정, 가격 동일·미갱신, 쿠폰 중복 요청·실패, 알림 오발송 상황을 확인한다.
- **효과 검증:** 재방문·상세 조회·구매 이동 기록을 확인하고, 인터뷰로 방문 이유를 보완한다. 단순 지표 상승만으로 가격 변동의 효과를 단정하지 않는다.

| 참여 기록 | 브라우저 익명번호 또는 참여번호 방식, 결과·쿠폰 재확인 방법 |

## 23. 반영하지 않는 제안

- **매출 규모 추정:** 실제 판매량, 전환율, 객단가, 원가율이 없어 수치를 제시하지 않는다. 기업 데이터 확보 후 보수·기준·공격 시나리오로 별도 산출한다.
- **38%p 상한 초과 이벤트:** 가격 안전 원칙과 RFP 절대 상한 조건에 어긋나 채택하지 않는다. 추가 혜택은 38%p 안에서 재배분하거나 배송비·사은품 등 가격 외 혜택으로 검토한다.
- **빵 도감·씰 수집 콘텐츠:** [[makji-stock-prototype]] 전제에 따라 제외한다.
