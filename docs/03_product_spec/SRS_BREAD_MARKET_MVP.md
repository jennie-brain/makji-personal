# MAKJI STOCK 빵마켓 MVP SRS

문서 버전: 1.1<br>
기준일: 2026-09-15<br>
상태: MVP 구현 기준 초안<br>
연계 PRD: `PRD_BREAD_MARKET_MVP.md` 버전 1.0

이 문서는 PRD의 제품 요구사항을 구현·시험 가능한 시스템 요구사항으로 구체화한다. 별도 표기가 없는 한 요구사항의 우선순위는 MVP 필수(Must)다.

## 1. 시스템 범위

MAKJI STOCK은 외부 환율·검색트렌드 데이터를 매일 수집해 다섯 상품의 가격을 계산하고, 모바일 웹에서 가격 목록·이력·할인 근거를 제공한 뒤 막지 자사몰로 연결하는 독립 서비스다. 주문, 결제, 회원, 재고는 자사몰이 담당한다.

## 2. 논리 구성

```text
환율 API ─┐
          ├─ 수집·검증 ─ 가격 계산 ─ 가격 스냅샷 저장 ─ 공개 API ─ 모바일 웹
검색 API ─┘                                                   └─ makji.kr
```

### 2.1 시스템 경계

- MAKJI STOCK: 외부 데이터 수집, 입력 검증, 가격 계산, 가격 스냅샷 저장, 공개 API, 모바일 웹, 외부 이동 기록을 담당한다.
- 외부 데이터 제공자: 확정 USD/KRW 환율과 상품별 검색지수를 제공한다.
- 막지 자사몰: 상품 상세, 재고, 주문, 결제, 회원 정보를 담당한다.
- 운영자는 상품 기준가·검색어 묶음·원 단위 처리 정책·기능 플래그를 배포 가능한 설정으로 관리한다. 운영 화면 자체는 MVP 범위가 아니다.

## 4. 계산 요구사항

- SR-CALC-01: 환율 하락률은 최근 두 영업일의 확정 환율로 계산한다.
- SR-CALC-02: 하락률이 0 이하이면 환율 할인은 0이다.
- SR-CALC-03: 환율 할인은 28%p를 초과할 수 없다.
- SR-CALC-04: 검색 할인은 검색지수 × 0.1이며 10%p를 초과할 수 없다.
- SR-CALC-05: 총 할인은 두 할인 합계이며 38%p를 초과할 수 없다.
- SR-CALC-06: 최종가격은 정가 기준으로 매일 재계산한다.
- SR-CALC-07: 원 단위 반올림·절사 규칙은 설정값으로 관리하고 자사몰과 동일하게 적용한다.
- SR-CALC-08: 입력값과 중간값, 캡 적용 전후 값을 감사 가능하게 저장한다.
- SR-CALC-09: 계산 중간값은 최소 소수점 여섯째 자리까지 유지하고, 최종 단계에서만 원 단위 정책을 적용한다.
- SR-CALC-10: 할인율 표시는 저장된 계산값을 기준으로 소수점 첫째 자리까지 반올림한다. 표시 반올림이 최종가격을 다시 계산하는 입력으로 사용되어서는 안 된다.

계산식은 다음과 같다.

```text
fx_decline_rate = (fx_previous - fx_current) / fx_previous * 100
fx_discount_raw = max(0, fx_decline_rate * 0.28 * 50)
fx_discount = min(28, fx_discount_raw)
trend_discount = min(10, search_index * 0.1)
total_discount_raw = fx_discount + trend_discount
total_discount = min(38, total_discount_raw)
unrounded_price = base_price * (1 - total_discount / 100)
final_price = apply_rounding_policy(unrounded_price)
```

## 5. 배치와 상태 전이

1. 08:45 수집 작업을 시작한다.
2. 스키마, 범위, 기준일, 중복 여부를 검증한다.
3. 다섯 상품의 가격을 계산하고 `scheduled`로 저장한다.
4. 자사몰 적용 가능 가격과 대조한다.
5. 09:00 검증 성공 건을 원자적으로 `published`로 전환한다.
6. 입력 실패 시 이전 값을 무조건 재사용하지 않고 실패 유형을 판정한다.
7. 정상 비영업일은 `carry_forward=true`, 장애는 `held` 또는 `blocked`로 구분한다.

### 5.1 상태 정의

| 상태 | 의미 | 사용자 노출 |
|---|---|---|
| scheduled | 계산과 사전 검증이 완료됐으나 아직 공개 전 | 직전 published 값 유지 |
| published | 자사몰 가격 대조까지 성공해 공개됨 | 신규 가격 노출 |
| held | 일시 장애나 입력 지연으로 신규 공개를 보류함 | 직전 published 값과 최종 갱신 시각 노출 |
| blocked | 데이터 무결성 또는 자사몰 불일치로 운영 확인이 필요함 | 영향 상품의 구매 CTA 비활성화 |

공개 전환은 표시일 단위로 원자적으로 수행한다. 일부 상품만 검증에 실패하면 전체 공개를 보류하는 것을 기본 정책으로 하되, 상품 단위 공개가 필요하면 출시 전에 운영 정책과 사용자 고지를 별도로 승인해야 한다.

## 6. API 요구사항

### GET /v1/market/today

응답: 가격 표시일, 공개 시각, 데이터 상태, 상품 목록, 정가, 최종가격, 총 할인율, 전일 대비 가격·등락 방향, 최근 가격 요약. 정렬 쿼리는 `discount_desc`(기본값), `price_asc`, `name_asc`만 허용한다.

### GET /v1/products/{id}/prices?period=14d

응답: 상품 정보, 기간별 가격 시계열, 최고가, 최저가, 오늘 가격.

### GET /v1/products/{id}/breakdown?date=YYYY-MM-DD

응답: 환율 할인, 검색트렌드 할인, 총 할인, 각 기준일, 이월 여부, 사용자용 설명.

### POST /v1/outbound-clicks

입력: product_id, pricing_date, surface, anonymous_session_id.<br>
응답: 검증된 자사몰 URL. 민감정보는 수집하지 않는다.

### 6.1 공통 API 규칙

- 날짜는 `YYYY-MM-DD`, 시각은 시간대가 포함된 ISO 8601 형식으로 반환한다.
- 금액은 원 단위 정수, 할인율은 퍼센트포인트 단위 숫자로 반환한다.
- 공개 조회 API는 존재하지 않는 상품에 `404`, 잘못된 기간·날짜에 `400`, 일시 장애에 `503`과 안정적인 오류 코드를 반환한다.
- 응답에는 `calculation_version`과 `last_successful_at`을 포함해 데이터 최신성을 판별할 수 있게 한다.
- `store_url`은 서버의 `makji.kr` 허용 목록에서 생성하며 클라이언트가 전달한 임의 URL을 리디렉션에 사용하지 않는다.
- 오늘 시세 응답은 09:00 공개 전환 후 캐시를 무효화하며, 같은 공개 버전에서는 일관된 값을 반환한다.

## 7. 프론트엔드 요구사항

- 375~430px에서 핵심 레이아웃이 잘리지 않아야 한다.
- 터치 대상은 최소 44×44pt다.
- 본문 기본 크기는 15~17px, 보조 텍스트는 12px 이상이다.
- 차트는 SVG 또는 Canvas로 렌더링하고 동일 정보를 텍스트로도 제공한다.
- 할인 근거는 포커스가 모달 안에 머무는 접근 가능한 바텀시트로 제공한다.
- Escape, 닫기 버튼, 바깥 영역 선택으로 모달을 닫을 수 있어야 한다.
- 모션 감소 설정에서는 슬라이드 애니메이션을 제거한다.
- 목록 기본 정렬은 할인율 내림차순이며 동률이면 `display_order` 오름차순을 적용한다.
- 가격 상승·하락 정보는 색상만으로 구분하지 않고 아이콘이나 문구를 함께 제공한다.
- 자사몰 이동 전 확인 화면에는 상품명, 최종가격, `makji.kr` 도메인을 표시한다.
- 하단 내비게이션은 `홈·빵마켓·이벤트`만 제공하고 빵마켓 화면에서는 빵마켓을 활성 상태로 표시한다. 홈·이벤트 상세 화면은 MVP 구현 범위가 아니다.

## 9. 오류 처리

- 환율 API 장애: 신규 공개를 보류하고 마지막 정상 공개 시각을 유지한다.
- 검색 API 장애: 임의의 0 또는 평균값으로 대체하지 않고 상태를 `held`로 기록한다.
- 기준일 역전·중복: 계산을 중단한다.
- 총 할인 38% 초과: 38%로 제한하고 초과폭을 저장한다.
- 표시가격과 자사몰 가격 불일치: 해당 상품의 구매 연결을 비활성화한다.
- 상품 이미지 실패: 브랜드 기본 대체 이미지를 사용하되 가격 정보는 유지한다.

## 11. 시험 기준

- 경계값: 환율 할인 0·28, 검색 할인 0·10, 총 할인 38.
- 비영업일, 연속 휴일, 윤년, 기준일 누락을 검증한다.
- 5종 전체에서 정가·최종가격·할인율의 수학적 일치를 검증한다.
- 차트 기간 전환, 바텀시트 열기·닫기, 자사몰 이동을 E2E 시험한다.
- 402×874pt에서 텍스트 겹침과 가로 스크롤이 없어야 한다.

### 11.1 핵심 인수 기준

| ID | Given | When | Then |
|---|---|---|---|
| AC-01 | 다섯 상품의 정상 입력이 준비됨 | 09:00 공개 작업이 완료됨 | 동일 표시일의 다섯 상품이 한 번에 `published`로 조회됨 |
| AC-02 | 환율이 전 영업일과 같거나 상승함 | 가격을 계산함 | 환율 할인은 0%p이며 검색 할인만 적용됨 |
| AC-03 | 합산 원시 할인율이 38%p를 초과함 | 가격을 계산함 | 총 할인율은 38%p이고 원시값과 제한 적용값이 모두 저장됨 |
| AC-04 | 사용자가 기간을 7일·14일·1개월로 변경함 | 가격 이력을 조회함 | 선택 기간의 날짜·가격, 최고가·최저가·오늘 가격이 일치함 |
| AC-05 | 사용자가 할인 근거를 엶 | 키보드나 스크린리더로 탐색함 | 포커스가 바텀시트 안에 유지되고 세 가지 닫기 방식이 동작함 |
| AC-06 | 표시가격과 자사몰 적용가격이 다름 | 공개 전 대조를 수행함 | 신규 공개가 보류되고 구매 CTA가 활성화되지 않음 |
| AC-07 | 외환시장 비영업일임 | 정상 이월 작업을 수행함 | 직전 정상 산출값, 실제 기준일, 이월 상태가 함께 표시됨 |
| AC-08 | 사용자가 구매 계속하기를 선택함 | 외부 이동 API가 성공함 | 선택 상품의 허용된 `makji.kr` URL로만 이동함 |

## 12. 배포와 롤백

- 가격 계산 버전과 프론트엔드 버전을 독립 배포한다.
- 배치 공개 전 스냅샷을 보관하고 이전 정상 가격으로 복구할 수 있어야 한다.
- 기능 플래그로 가격 공개와 구매 연결을 각각 차단할 수 있어야 한다.
- API 키는 서버 비밀 저장소에서 관리하고 저장소나 브라우저에 포함하지 않는다.
