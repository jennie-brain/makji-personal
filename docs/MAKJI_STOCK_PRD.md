## 2. 배경 및 목표

**핵심 문장:** 시장 데이터를 활용한 참여 경험으로 MAKJI 자사몰의 재방문과 구매 전환을 유도한다.

### 2-1. 기업 RFP 요구사항
- 외부 시장 데이터 기반 Bread Market의 실제 동작 MVP 구현·검증
- 플랫폼 이용 → 상품 관심 → 구매 전환 → 재방문으로 이어지는 구조 설계

### 2-2. 해결하려는 문제
- 배경: MAKJI의 B2B → B2C 시장 확장 전략의 일환
- 문제: 구매할 일이 없어도 자사몰에 재방문할 이유가 없음

### 2-3. 서비스 방향
- 참여 동기: 오늘 가격 확인, 저렴한 구매 기회, 예측 결과에 대한 궁금증
- 선택한 방향: 가격 탐색과 예측 이벤트를 연결해 다음 날 다시 방문할 이유를 만든다

### 2-4. 목표
| 주체 | 목표 |
| --- | --- |
| 사용자 | 오늘의 가격과 참여 혜택을 확인하고 상품을 탐색한다 |
| 기업 | 재방문과 상품 관심이 실제 구매로 연결되는지 확인한다 |
| 프로젝트 | 데이터 수집부터 가격·쿠폰 반영, 행동 측정까지 동작하는 MVP를 만든다 |

### 행동별 연결
| 단계 | 사용자 행동 | 제공 기능 | 다음 행동 | 측정 지표 |

- 익명 참여자와 실제 구매자를 연결해 측정할 수 있는 범위

## 4. 핵심 기능 (MVP)

**핵심 문장:** 오늘 가격을 비교하고 내일 가격을 예측하는 경험을 중심으로 구성한다. 이 장은 기능의 진행 규칙·결과·보상을 정의하며, 화면 표현은 5장에서 다룬다.

### 4-1. 오늘의 빵시장
- **대상:** MAKJI 상품 10종 (부록 B 참조)
- **제공 정보:** 오늘 시세, 가격 변화, 상품별 가격 추이
- **사용자 행동:** 상품 비교 → 상세 확인 → 구매 이동
- **결과:** 관심 상품과 적용 가능한 혜택을 확인하고 카페24 구매로 연결
- **협의 필요:** 화면에 표시할 가격 변화 기준(기본가격 대비 vs. 전일 대비), 가격 갱신 시각, 판매 종료·품절·가격 미갱신 시 처리

### 4-2. 내일 가격 예측과 보상
| 항목 | 내용 / 협의 필요 사항 |
| --- | --- |
| 예측 대상 | 10종 중 매일 1개를 랜덤 선정한 상품의 내일 가격 방향 |
| 비교 기준 | 오늘 가격과 내일 가격(반올림 후 실제 적용가) 비교 |
| 상품 선정 | 랜덤 선정. 모든 사용자에게 동일 상품으로 노출할지 결정 필요 |
| 참여 조건 | 익명 ID + 서버 저장. 1일 1회, 마감 시각 결정 필요 |
| 결과 판정 | 오른다 / 내린다(A/B). 가격 동일(보합) 시 처리 방식 결정 필요 |
| 보상 | 예측 성공 시 할인코드 또는 임시 할인 URL 제공. 금액·사용기간·최소구매금액·중복적용 조건 결정 필요 |
| 비정상 상황 | 데이터 미갱신·가격 미반영·쿠폰 발급 실패 시 처리 방식 결정 필요 |

### 4-3. 추가 콘텐츠 후보 (MVP 핵심 기능 아님)
- 지수(BREAD-DAQ 등 종합 지수), 뉴스, 빵운세, 빵 자르기 게임은 **후보**이며, 핵심 기능(오늘 시세·내일 예측) 완성도와 구매·재방문 기여도를 기준으로 포함 여부를 결정한다.
- 랭킹·구독 리워드는 현재 팀 기획에 **포함하지 않는다.**

## 6. 데이터 및 가격 정책

**핵심 문장:** 검색트렌드와 환율을 연결하는 이유와, 가격·보상을 적용하는 기준을 설명한다.

### 6-1. 데이터 선택과 연결 근거
| 데이터 | 연결 목적 | 확보 계획(API) | 확인할 사항 |
| --- | --- | --- | --- |
| 검색트렌드 | 상품별 관심도를 가격 혜택으로 반영 | NAVER DataLab 관련 API 검토 | 상품별 검색어, 조회 기간, 점수 환산 방법, 이용조건·비용 |
| USD/KRW 환율 | 공통 시장 변화를 가격에 반영 | 한국수출입은행 환율정보 API 검토 | 기준 시점, 휴일·결측 처리, 이용조건·비용 |
| 상품 정보 | 실제 상품과 시세 연결 | 기업 제공 자료 | 상품 ID·가격·원재료·이미지·노출 승인 |
| 참여·구매 행동 | 성과 측정과 향후 개인화 | 서비스 기록 · 카페24 연동 검토 | 확보 항목, 식별 방법, 접근 권한 |

> RFP상 제시된 API 및 비용은 예시이며, 실제 사용 가능 여부와 조건은 연동 전 별도로 확인한다.
>
> **⚠️ KOSPI는 가격 산정에서 제외한다.** 9/9 회의록에는 검색트렌드(60%)+KOSPI(25%)+환율(15%) 가중합 방식이 있었으나, 9/10 기획안 초안에서 **KOSPI를 완전히 배제**하고 검색트렌드·환율 2개 지표로 조정했다(이후 프로토타입에서도 "코스피 100% 영구 배제"로 확정 반영됨). 본 PRD는 후자를 기준으로 한다.

### 6-2. 가격 결정 원칙 (팀 제안, 확정 아님)
- 검색 관심도가 높을수록 가격을 낮추는 방향으로 반영한다.
- 환율은 합산 대상이므로 최종 가격은 상승하거나 하락할 수 있다.
- 매일 **기본가격**에서 다시 계산하고, 가격대별 한도 적용 후 10원 단위로 반올림한다. (전일 가격 기준 누적 계산 아님)
- **현재 검토값:** 검색트렌드 ±5%, 환율(전일비 × 3배 증폭) ±3% 제한 → 합산 결과 최대 ±8%
- **협의 필요:** 저가 상품의 상한을 기존 검토안인 ±10%로 유지할지, 위 계산상 최대치인 ±8%로 통일할지 결정
- 기본가격 대비 조정률과 전일 대비 등락률은 다른 값이다. 화면에 어느 값을 표시할지 결정 필요
- RFP는 일일 할인·이벤트 자동 추천을 예시로 제시하나, "기본가격보다 높아질 수 있는 판매가" 정책은 팀 제안이므로 기업과 적용 범위를 확인해야 한다.

### 6-3. 데이터 기준과 예외 처리 (협의 필요 항목)
- 조회 주기와 가격 반영 시각
- 데이터 기준일 (어느 날짜의 검색트렌드·환율을 오늘 가격에 반영하는가)
- 휴일·미공시·조회 실패 시 처리 (이전 값 유지 vs. 갱신 보류)
- 검색 점수 환산 방식 (조회 기간, 상품별 검색어, 0~1 환산 방식)
- 예측 정답 판정: 오늘과 내일의 반올림 후 실제 적용 가격을 비교하는 안. 가격 동일·미갱신 시 판정 방법 결정 필요

## 7. 구현·운영 계획

**핵심 문장:** 외부 데이터가 실제 가격·쿠폰으로 반영되고 운영 상태를 확인할 수 있어야 한다.

### 7-1. 연결 흐름
```
외부 API → 팀 서버 수집·검증 → 가격·프로모션 계산 → 카페24 상품가·쿠폰 반영 → 사용자 화면·성과 기록
```
- RFP상 2주차에 배포 서버 URL 제공 후 기업의 Client ID/Secret 발급, 앱 등록, 팀별 무료체험몰 테스트 절차가 안내되어 있음
- **협의/작성 필요:** 실제 연동할 API·담당자·테스트 스토어·배포 환경·갱신 시각, 데이터 수집·가격 반영 실패 시 대체 처리 및 운영자 확인 방법, API 키 관리·코드 구조·배포/복구 방법 인수인계 문서화

## 9. MVP 범위와 확장 계획

**핵심 문장:** Bread Market의 데이터 연동·참여·구매 연결을 우선 구현하고, 확장 서비스는 설계 문서로만 제시한다(구현 대상 아님).

| 구분 | 범위 | 결과물 |
| --- | --- | --- |
| RFP 구현 대상 | Bread Market | 서비스 기획서, 외부 API가 동작하는 MVP, 기술 인수인계 문서 |
| **팀 MVP** | 오늘 시세, 상품 목록·상세, 가격 추이, 내일 가격 예측·보상, 구매 연결 | 실제 동작 화면 및 시나리오 검증 |
| 추가 기능 후보 | 지수·뉴스, 빵운세, 빵 자르기 게임 | 핵심 구현 이후 우선순위 결정 |
| **RFP 설계 대상 (구현 아님)** | Bakery ETF, FX Bakery, Bread Index | 각 서비스의 기능·정책·운영 설계 문서만 작성 |

> **참고:** '우울해서 빵 샀어' 감정 헷지 처방전은 9/9 회의록·9/10 기획안 어디에도 MVP 또는 확장 설계 대상으로 등장하지 않는다. v1.0 와이어프레임 문서에서만 등장한 항목이므로, 계속 추진할지 여부는 팀 확인이 필요하다.

### 9-1. 확장 서비스 설계 (설계 문서만, MVP 구현 범위 아님)
| 서비스 | 반드시 작성할 내용 | Bread Market과 연결 지점 |
| --- | --- | --- |
| Bakery ETF | 화면 구성, 사용자 여정, 추천 로직, 운영 시나리오 | 관심 상품·선호도·구매이력 기반 개인 맞춤 구성 |
| FX Bakery | 적용 조건, 대상 상품, 할인·쿠폰 정책, 운영 절차 | 환율 반영을 국가별 원료·제품 프로모션으로 확장 |
| Bread Index | 산출 기준, 가중치, 업데이트 주기, 시각화 방식 | 판매·재구매·검색·SNS 반응·만족도 기반 브랜드 지표 |

### 9-2. 개인화 추천 설계 시 보완할 점
- RFP는 개인화 추천의 실용성을 높은 중요도로 평가한다.
- 초기 구매 데이터가 적다는 전제를 반영해야 한다.
- 예시 제안: 첫 방문 시 선호도 선택을 받고, 이후 행동·구매이력으로 추천을 보완한다.
- **작성 필요:** 데이터가 적을 때 추천 방법 → 데이터 축적 후 추천 방법 → 재방문·구매 기여 검증 방법
