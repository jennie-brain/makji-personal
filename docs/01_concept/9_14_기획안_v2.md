## 1. 서비스 소개

> MAKJI STOCK은 **검색트렌드**와 **환율**을 반영해 매일 달라지는 빵값을 보여주는 서비스입니다.
> 

사용자는 **MAKJI STOCK에서 오늘 빵값을 확인하고, 구매할 상품을 선택하면 막지 자사몰로 이동**합니다. 

두 사이트는 별도로 운영하며, 실제 주문과 결제는 막지 자사몰에서 진행합니다.

| 항목 | 내용 |
| --- | --- |
| 서비스명 | MAKJI STOCK |
| 타깃 사용자 | 매일 달라지는 빵 시세와 혜택을 확인하며, 단순 구매를 넘어 새로운 구매 경험을 즐기는 온라인 베이커리 소비자 |
| 핵심 가치 | 매일 새로운 가격을 확인하고 원하는 빵의 구매 시점을 판단하는 경험 |
| 핵심 메시지 | 매일 오전 9시, 오늘의 빵값이 열립니다 |
| 대표 체감 수치 | 4,500원 빵 기준 하루 평균 약 217원 변동 |

### 방문 동기

매일 달라지는 빵값을 확인하고, 원하는 빵을 저렴하게 살 기회를 찾기 위해 방문합니다.

**핵심 이용 경험:** 오늘 빵값 확인 → 상품 비교 → 막지 자사몰에서 구매

**추가 참여 경험:** 내일 가격 예측 → 다음 날 결과 확인 → 성공 시 할인 쿠폰

가격 할인 자체가 목적이 아니라, 오늘의 가격을 확인하는 행동이 상품 탐색과 재방문으로 이어지게 하는 것이 핵심입니다. 개인의 검색 한 번이 즉시 할인으로 바뀌는 구조는 아니며, 확정된 환율 데이터와 상품별 검색 관심도를 정해진 산식으로 반영합니다.

## 2. 기획 배경

> 매일 달라지는 빵값으로 MAKJI STOCK에 다시 방문할 이유를 만들고, 관심 상품의 구매를 막지 자사몰로 연결합니다.
> 

### 2-1. 기업의 요구

- 기업 RFP는 외부 시장 데이터를 식품 구매 경험에 연결해 **상품 관심·재방문·구매 전환**을 유도하는 기능을 요구합니다.
- 메타 광고용 이벤트 페이지와 SNS 홍보 소재를 통해 신규 고객을 유입하고, 자사몰 구매로 연결하는 프로모션도 요구합니다.

### 2-2. 기획 방향

구매할 상품이 정해져 있지 않아도, **오늘 가격이 궁금해서 상품을 둘러보게 하는 것**이 출발점입니다.

검색트렌드와 환율로 매일 가격을 계산하고, 상품별 가격 추이를 제공합니다. 사용자는 가격을 비교한 뒤 구매를 결정하거나 다음 날 다시 확인할 수 있습니다. 

### 2-3. 프로젝트 목표

| 대상 | 목표 |
| --- | --- |
| 사용자 | 오늘 가격과 이전 가격을 비교하고 구매할 상품을 선택 |
| MAKJI STOCK | 가격 확인을 위한 반복 방문과 상품 탐색 유도 |
| 막지 자사몰 | 관심 상품 페이지로의 유입과 실제 구매 기회 확대 |

### 2-4. 소비자가 기억할 경험

> 할인은 무작위 이벤트가 아니라, 빵 자체를 매일 관심의 중심에 놓는 장치입니다.

소비자 경험은 다음 세 단계로 단순화합니다.

1. **아침 시세 확인:** 사용자는 “오늘 막지빵은 얼마일까?”라는 궁금증으로 접속합니다.
2. **오늘 가격 공개:** 오전 9시에 오늘 가격, 어제 대비 변동액, 가격이 달라진 이유를 확인합니다.
3. **재방문 습관:** 오늘과 내일의 가격을 비교하거나 예측 결과를 확인하기 위해 다시 방문합니다.

SNS와 광고에서는 복잡한 산식보다 다음과 같은 소비자 언어를 우선 사용합니다.

- “오늘 막지빵, 어제보다 얼마나 달라졌을까요?”
- “매일 오전 9시, 오늘의 빵값이 열립니다.”

## 3. 서비스 이용 흐름

> 가격을 확인하는 곳은 MAKJI STOCK, 주문하고 결제하는 곳은 막지 자사몰입니다.
> 

### 3-1. 방문부터 구매까지

| 구간 | 사용자 경험 | 이용 장소 |
| --- | --- | --- |
| 이용 전 | 광고 또는 공유 링크에서 서비스를 발견하고 접속 | 외부 유입 채널 → MAKJI STOCK |
| 이용 중 | 오늘 빵값 확인 → 상품 비교 → 가격 추이·상품 정보 확인 | MAKJI STOCK |
| 구매 이동 | ‘막지에서 구매하기’를 눌러 해당 상품 페이지로 이동 | MAKJI STOCK → 막지 자사몰 |
| 이용 후 | 자사몰에서 주문·결제하거나, 다른 날 MAKJI STOCK에서 가격 재확인 | 막지 자사몰 / MAKJI STOCK |

> 오늘 예측에 참여 → 다음 날 MAKJI STOCK 재방문 → 결과 확인 → 성공 시 쿠폰 수령 → 자사몰에서 사용
> 

## 4. 핵심 콘텐츠

> 오늘의 빵시장이 중심 콘텐츠이며, 내일 가격 예측은 재방문을 돕는 추가 콘텐츠입니다.
> 

### 4-1. 오늘의 빵시장

| 항목 | 내용 |
| --- | --- |
| 대상 상품 | MAKJI MVP 상품 5종 |
| 오늘 시세 | 검색트렌드와 환율을 반영해 계산한 상품별 가격 |
| 가격 변화 | 비교 기준과 함께 표시하는 가격 차이·비율 |
| 가격 추이 | 날짜별 가격을 확인하는 그래프 |
| 구매 연결 | 선택한 상품의 막지 자사몰 페이지로 이동 |

사용자는 오늘 가격과 이전 가격을 비교해 구매할 상품을 고릅니다. 

가격 변화의 화면 표시 기준은 기본가격 대비입니다.

### 4-2. 내일 가격 예측

오늘 선정된 빵의 내일 가격이 오를지 내릴지 선택합니다. 

다음 날 가격이 확정되면 예측 결과를 안내하고, 성공한 참여자에게 할인 쿠폰을 제공하는 안입니다.

| 항목 | 현재 기획 |
| --- | --- |
| 예측 상품 | MVP 5종 중 무작위로 선정한 상품 |
| 선택지 | 오른다 / 내린다 |
| 비교 기준 | 해당 상품의 오늘 가격과 내일 가격 |
| 결과 | 예측 성공 또는 실패 안내 |
| 보상 | 성공 시 할인 쿠폰 제공 제안 |

### 4-3. 자사몰 유입 프로모션

메타 광고와 SNS 홍보 소재를 통해 신규 고객을 MAKJI STOCK으로 유입하고, 이벤트 참여를 자사몰 구매로 연결합니다.

- **데일리 뉴스레터:** 시장 정보와 오늘의 빵 콘텐츠 제공
- **빵 자르기 게임:** 가볍게 참여할 수 있는 이벤트 콘텐츠
- **오늘의 빵 운세:** 매일 확인할 수 있는 데일리 콘텐츠

**유입 흐름:** SNS·메타 광고 → 이벤트 페이지 → Bread Market·상품 상세 → 막지 자사몰 구매

## 6. 외부데이터와 가격 정책

> 확정된 환율 데이터가 일별 가격 변화를 만들고, 상품별 검색 관심도가 추가 혜택을 더합니다.
> 

### 6-1. 사용하는 데이터

| 구분 | 데이터 | 활용 목적 | 확보 계획 |
| --- | --- | --- | --- |
| 외부데이터 | NAVER 검색트렌드 | 상품별 관심도를 가격에 반영 | NAVER API HUB |
| 외부데이터 | USD/KRW 환율 | 금융시장 변화를 상품 가격에 공통 반영 | 한국수출입은행 관련 API |
| 기업 자료 | 상품명·기본가격·원재료·이미지 | 실제 상품과 시세 연결 | 기업 제공·협의 |
| 서비스 기록 | 방문·상품 조회·예측·쿠폰 기록 | 운영과 효과 검증 | 우리 서버에 저장하는 구조 설계 |

### 6-2. 가격 결정 원칙

1. 매일 오전 9시, 전날까지 확정된 원/달러 환율과 전날 검색지수를 확인합니다.
2. 영업일이 연속되는 일반적인 평일에는 이틀 전 환율과 하루 전 환율을 비교합니다. 예를 들어 오늘이 수요일이면 월요일 환율과 화요일 환율을 비교합니다.
3. 실제 시스템은 달력 날짜가 아니라 API에서 확인되는 가장 최근 두 영업일의 환율을 비교합니다. 월요일이나 공휴일 다음 날에도 같은 기준을 적용합니다.
4. 환율이 하락한 경우에만 환율할인을 적용하며 최대 28%p까지만 반영합니다. 환율이 상승하거나 변동이 없으면 환율할인은 0%p입니다.
5. 상품별 검색지수는 최대 10%p의 검색쿠폰으로 변환합니다.
6. 환율할인과 검색쿠폰의 합이 38%p 이하이면 계산된 값을 그대로 적용하고, 38%p를 넘으면 총할인율은 38%p까지만 적용합니다.
7. 전날 가격에 할인을 누적하지 않고 매일 정가에서 다시 계산합니다.
8. 표시가격과 자사몰 실제 결제가격은 일치해야 하며, 원 단위 처리 규칙은 자사몰 연동 정책에 맞춰 확정합니다.

38%p는 현재 가격 엔진의 하드캡입니다. 다만 이 상한이 실제 상품별 수익성을 보장한다는 뜻은 아니므로, 상품별 원가율과 마진을 확인한 뒤 최종 운영 상한을 확정합니다.

### 6-3. 현재 가격 산식

| 요소 | 계산 및 적용 방식 | 적용 한도 |
| --- | --- | --- |
| 환율 하락률 | 이틀 전 환율에서 하루 전 환율이 얼마나 내려갔는지 백분율로 계산합니다. 실제 시스템은 API에서 확인되는 최근 두 영업일의 확정 환율을 사용합니다. | 환율이 상승하거나 같으면 0%로 봅니다. |
| 환율할인 | 환율 하락률에 `0.28 × 50`을 곱합니다. 계산값이 28%p를 넘으면 28%p까지만 적용합니다. | 최대 28%p |
| 검색쿠폰 | 네이버 검색지수(0~100)에 0.1을 곱합니다. | 최대 10%p |
| 총할인율 | 환율할인과 검색쿠폰을 더합니다. 합이 38%p를 넘으면 38%p까지만 적용합니다. | 최대 38%p |
| 오늘 가격 | 정가에서 총할인율만큼을 뺍니다. | 전일 가격이 아닌 정가 기준 |

91일 실데이터 백테스트에서 총할인율 중앙값은 12.0%p, 평균은 12.5%p, 최대는 30.9%p였습니다. 4,500원 빵을 기준으로 평균 할인금액은 약 563원이며, 일별 가격의 평균 변동폭은 약 217원입니다. 두 금액은 각각 ‘평균 할인 수준’과 ‘전일 대비 가격 변화’를 뜻하므로 구분하여 표시합니다.

### 6-4. 표시 기준과 데이터 갱신

- **정가 대비 할인율:** 오늘 가격에 적용된 환율할인과 검색쿠폰의 합계입니다.
- **전일 대비 변동액·변동률:** 오늘 가격이 직전 공개가격과 얼마나 달라졌는지 보여줍니다.
- 가격은 매일 오전 9시에 갱신하며, 전날 검색지수와 그 시점까지 API에서 확인된 원/달러 환율(USD/KRW, 1달러당 원화)을 사용합니다.
- 영업일이 연속되는 일반적인 평일에는 이틀 전 환율과 하루 전 환율로 하락률을 계산합니다. 실제 시스템은 달력 날짜가 아니라 API에서 확인되는 가장 최근 두 영업일의 확정 환율을 사용합니다.
- 외환시장 비영업일에는 마지막 영업일에 정상적으로 계산된 환율 하락률을 그대로 적용하고, 화면과 운영 기록에 가격 표시일·환율 기준일·검색량 기준일을 각각 기록합니다.
- 데이터 조회 실패와 정상적인 비영업일 이월을 구분하여 기록합니다. 예상보다 긴 연속 이월은 운영 경보 대상으로 관리합니다.
- 현재 백테스트는 모닝빵 단일 키워드 기준이므로 실제 적용 전에 대상 상품 전체의 검색어 묶음과 지수 분포를 검증합니다.

### 6-5. 가격 상한 가드레일

총할인율은 시스템에서 38%p를 절대 초과하지 않도록 제한합니다. 운영 가드레일은 상한까지 남은 비율보다 하드캡이 얼마나 자주, 얼마나 크게 작동하는지를 중심으로 관리합니다.

#### 기록 항목

- **원시 환율할인:** 28%p 개별 캡을 적용하기 전 `max(0, 환율 하락률 × 0.28 × 50)` 계산값입니다.
- **캡 적용 전 원시 할인율:** 원시 환율할인과 검색쿠폰을 합산한 값입니다. 개별 캡과 총 38%p 하드캡이 얼마나 자주 개입하는지 확인하기 위해 저장합니다.
- **최종 할인율:** 원시 환율할인에 28%p 개별 캡을 적용하고 검색쿠폰을 더한 뒤 총 38%p 하드캡을 적용한 값입니다.
- **상한 초과폭:** `max(0, 캡 적용 전 원시 할인율 − 38%p)`로 계산합니다.
- **상한 도달일:** MVP 5종 중 한 상품 이상이 최종 할인율 38%p에 도달한 날짜입니다.
- **상한 적용 상품일 비율:** `최근 7일 동안 상한에 도달한 상품일 수 ÷ 전체 상품일 수 × 100`으로 계산합니다. 5종을 7일 운영하면 전체 상품일은 35건입니다.

#### 잠정 경보 기준

| 단계 | 조건 | 시스템 처리 | 담당자 조치 |
| --- | --- | --- | --- |
| 정상 | 최근 7일 상한 도달 0일이고 상한 적용 상품일 비율 5% 미만 | 정상 적용 | 정기 모니터링 |
| 주의 | 최근 7일 상한 도달 1일, 상한 적용 상품일 비율 5% 이상 또는 캡 적용 전 원시 할인율 38%p 초과 | 가격 적용 후 운영 알림 | 원본 환율·검색지수와 데이터 기준일 확인 |
| 경고 | 최근 7일 상한 도달 2일 이상, 2일 연속 도달, 상한 적용 상품일 비율 10% 이상, 상한 초과폭 5%p 이상 또는 하루 5종 중 3종 이상 도달 | 운영·재무 담당자에게 경고 | 데이터 오류 확인 후 환율 승수와 검색쿠폰 산식 검토 |
| 즉시 차단 | 캡 적용 전 원시 할인율 50%p 이상, 입력 데이터 허용 범위 이탈, 데이터 기준일 확인 불가 또는 표시가격과 결제가격 불일치 | 신규 가격 공개 또는 구매 연결 중지 | 원인을 수정하고 재검증한 뒤 운영 재개 |

91일 백테스트에서는 최대 할인율이 30.9%p였고 38%p 상한 도달은 0일이었습니다. 위 기준은 MVP의 잠정 운영 기준이며, 실제 운영 데이터가 30일 이상 축적되면 상한 도달 분포와 상품별 수익성을 바탕으로 조정합니다. 38%p 자체가 상품별 손익 안전성을 보장하는 것은 아니므로, 재무팀은 실제 원가와 마진을 검토해 상품별로 더 낮은 운영 상한을 정할 수 있습니다.

## 부록 B. 상세 가격 계산

아래는 91일 실데이터 백테스트에 사용한 현재 가격 산식입니다. 실제 운영 전에는 상품 전체의 검색 키워드, 상품별 원가·마진, 카페24 가격 적용 방식을 추가로 검증해야 합니다.

### B-1. 계산식

- 오늘 가격을 계산하는 날을 D라고 합니다.
- 영업일이 연속되는 일반적인 평일에는 D-2 환율과 D-1 환율을 비교합니다. 예를 들어 D가 수요일이면 월요일 환율과 화요일 환율을 비교합니다.
- 실제 시스템에서는 달력 날짜가 아니라 API에서 확인되는 가장 최근 두 영업일의 확정 환율을 사용합니다.
- 환율 하락률 = `(D-2 환율 − D-1 환율) ÷ D-2 환율 × 100`
- 계산 결과가 0 이하이면 환율할인은 0%p입니다.
- 원시 환율할인 = `환율 하락률 × 0.28 × 50`
- 원시 환율할인이 28%p 이하이면 그대로 적용하고, 28%p를 넘으면 환율할인은 28%p까지만 적용합니다.
- 검색쿠폰 = `네이버 검색지수(0~100) × 0.1`이며 최대 10%p입니다.
- 캡 적용 전 원시 할인율 = `원시 환율할인 + 검색쿠폰`
- 총할인율은 환율할인과 검색쿠폰의 합입니다. 합이 38%p 이하이면 그대로 적용하고, 38%p를 넘으면 38%p까지만 적용합니다.
- 오늘 가격 = `정가 × (1 − 총할인율 ÷ 100)`
- 상한 초과폭은 캡 적용 전 원시 할인율에서 38%p를 뺀 값입니다. 계산값이 0보다 작으면 0%p로 기록합니다.
- 외환시장 비영업일에는 마지막 영업일에 정상적으로 계산된 환율 하락률을 그대로 적용합니다.

예: 정가 4,500원 상품의 환율할인이 11.87%p이고 검색쿠폰이 6.75%p이면 총할인율은 18.62%p입니다. 오늘 가격은 원 단위 기준 약 **3,662원**입니다. 실제 판매가격의 원 단위 반올림 또는 절사 정책은 카페24 연동 규칙에 맞춰 확정합니다.

### B-2. 91일 백테스트 요약

| 항목 | 결과 | 해석 |
| --- | --- | --- |
| 중앙 할인율 | 12.0%p | 절반의 관측일은 12.0%p 이하 |
| 평균 할인율 | 12.5%p | 4,500원 기준 평균 약 563원 할인 |
| 평균 일별 변동폭 | 4.82%p | 4,500원 기준 하루 평균 약 217원 변동 |
