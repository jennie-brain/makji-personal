## 2. 슬라이드 4 상세 — 기획 배경(WHY)

### 상단 메시지

> 막지는 B2B 중심의 제품 공급 경험을 바탕으로, 자사몰(B2C)을 새로운 성장축으로 확장하고 있다.
> 그러나 5월 초기 자사몰 운영에서 확인된 과제는 '제품을 파는 것'보다 '방문을 다시 오게 하고, 구매까지 이어지게 하는 것'이었다.

### 중앙 — 5월 초기 운영 데이터(실측)

| 관찰 | 데이터 | 해석 |
|---|---|---|
| 관심은 발생 | 로그인 90회 · 신규가입 40건 | 초기 고객 접점은 확보 |
| 관심 시간대와 결제 시간대가 다름 | 오전 8~10시 로그인 23회(25.6%)·결제금액 27.4만 원(8.0%) / 저녁 20~24시 로그인 18회(20.0%)·결제금액 96.8만 원(28.4%) | 유입이 몰리는 시간과 구매가 몰리는 시간이 어긋남 |
| 결제 상태 확인이 필요한 주문 존재 | 생성 주문 147건 중 결제금액 0원 39건(26.5%) — 이 중 37건은 결제수단이 '선불금' | 진짜 결제 이탈인지 선불금 처리 특성인지는 팀 확인 필요(단정 금지) |
| 측정의 빈칸 | 방문자·세션·유입경로 데이터 미확보, 두 데이터 간 연결키 없음 | D2C 퍼널을 측정하고 개선할 구조가 아직 없음 |

### 하단 결론

> 필요한 것은 한 번의 할인 행사가 아니라, 고객이 매일 가격을 확인할 이유를 갖고 '지금 살지, 내일을 기다릴지'를 판단하며 자사몰 구매로 자연스럽게 이어지는 반복 방문 구조다.

**각주(부차 근거)**: Wu et al.(2020) 현장실험 n=182, 시간제한 프로모션 온라인 효과 조사 n=501 — 시간제한·가격변동이 구매행동에 영향을 준다는 외부 근거로만 보조 배치. 슬라이드의 주 근거는 5월 실측 데이터.

**데이터 출처(저장소 미포함, 로컬 보관)**: `0909_막지 자사몰 5월 시간별분석 (2).csv`, `0909_막지 자사몰 5월 주문내역 (4).csv` — 두 파일 합계가 서로 다르므로(340.8만 원 vs 271.8만 원) 발표에서는 파일별로 출처를 명시해 인용한다.

## 3. 슬라이드 5·6 상세 — 시장 현황과 문제 / 문제정의와 솔루션

### 슬라이드 5 — 시장 현황과 문제 (3단 패널)

| 패널 | 내용 |
|---|---|
| ① 시장 문제 | 화제성 의존형 성장 한계(런던베이글·노티드 매출 부침) · 헬시플레저 대체재 이탈(20대 45.5%·30대 51.1% 단백질 제품 선택) · 원부자재·환율 원가압박(삼립 등 평균 9% 인상) |
| ② 경쟁 구도 | 직접경쟁자 널담(2018창업, 2019년 약 10억 → 2025년 328억 원·전년비104%↑) vs 맥락경쟁자(런던베이글뮤지엄·노티드·성심당·SPC·CJ더마켓) — 경쟁사 0/6이 가격 변동을 콘텐츠로 안 씀 |
| ③ 고객 이탈 지점 | "가격이 오르내인다"는 컨셉 자체가 사행성처럼 느껴져 진입을 거부(N1·정은숙, 시장분석06 BEST CASE 공동1위) · 처음 보는 개념이라 신뢰가 안 감(C2·김소민) |

3개 패널을 불릿 나열이 아니라 좌우 또는 3단 컬럼으로 배치해 "시장도 어렵고, 경쟁도 있고, 고객도 의심한다"는 그림이 한눈에 들어오게 한다. STOCK→자사몰 전환마찰(C3)은 여기 넣지 않는다 — 13번 핵심 리스크 슬라이드에서 이미 다룬다(중복 방지).

### 슬라이드 6 — 문제정의와 솔루션 (브릿지)

> **문제**: 정적인 가격과 검증되지 않은 개념으로는, 이미 화제성에 의존해 부침을 겪는 이 시장에서 반복 방문을 만들 수 없다.
>
> **솔루션**: MAKJI STOCK은 실제 환율·검색량 데이터로 가격을 매일(오전장·오후장) 움직여 콘텐츠로 만들고, 그 움직임의 근거를 투명하게 보여줘 신뢰를 얻으며, 고객이 원하는 방식(잠금 또는 예측)으로 혜택을 직접 고르게 한다.

이 슬라이드는 Executive Summary(2번)의 확장판 역할을 한다 — 5번에서 쌓은 증거(시장·경쟁·고객)를 한 문장의 문제정의로 압축하고, 곧바로 한 문장의 솔루션으로 답한 뒤, 7·8번(성공조건·차별화전략)에서 그 솔루션을 구체화한다.

## 4. 슬라이드 7 상세 — 성공 조건과 차별화 전략의 1:1 대응

성공 조건 3개는 각각 8번 슬라이드의 차별화 전략 3방향과 정확히 하나씩 대응한다 — 조건이 없으면 전략이 성립하지 않고, 전략이 조건을 실제 제품 기능으로 구현한다.

| 성공 조건 | ↔ | 차별화 전략 |
|---|---|---|
| ① 체감 — 진짜 외부데이터(환율·검색량)로 경제 흐름을 느끼게 함 | ↔ | ② 투명한 체감(사행성 아님) — 실제 데이터로 "왜 이 가격인지" 설명 |
| ② 주도적으로 고르는 혜택 — 잠금 또는 예측(안정형/공격형) 중 내가 원하는 방식으로 혜택을 가져간다 | ↔ | ③ 위험성향별 선택 리워드 |
| ③ 가격이 살아있다는 감각 — 주식시장처럼 매일(오전장·오후장) 움직이는 가격 자체가 콘텐츠 | ↔ | ① 가격의 콘텐츠화 |

**STOCK↔자사몰 전환 마찰은 이 목록에 없다** — 처음엔 성공조건 후보였지만, RFP가 STOCK과 자사몰의 결제 시스템을 분리하도록 못박은 구조적 제약이라 우리가 실행으로 완전히 없앨 수 있는 대상이 아니다(원클릭·자동인식으로 최소화는 가능). "실행하면 갖출 수 있는 조건"이 아니라 "안고 가야 할 제약"이라, 13번 핵심 리스크 슬라이드로 옮겼다. 시장분석06에서 AOS·DOS 전체 1위(C3)로 나온 만큼 중요도는 그대로 유지하되, 슬라이드의 성격(조건 vs 리스크)에 맞게 위치만 재배치한 것이다.

## 5. 슬라이드 10 상세 — 소비자 화면 흐름 (3개 흐름)

프로토타입 스크린샷이 아니라, 기능별로 사용자가 실제로 거치는 **논리적 흐름**을 3개로 나눠 보여준다. 세 흐름 모두 마지막은 "자사몰 이동·구매"로 끝나되, 각 흐름이 겨냥하는 사용자 심리와 관문이 다르다.

### 흐름 ① 기본 구매 전환 — 유입→온보딩→자사몰

가장 단순한 경로. 잠금도 예측도 쓰지 않고 그 자리에서 사는 사용자다.

```
SNS·광고 유입
  → 온보딩 5장(빵값이 왜 움직이나 ~ 어디서 사나)
  → Bread Market에서 오늘 가격 확인
  → 마음에 드는 상품 선택
  → "막지에서 구매하기" → 자사몰 이동
  → 회원가입·로그인 → 구매 완료
```

### 흐름 ② 가격 잠금 — 아침 방문, 오후 재방문

오전에 들어왔지만 "오후에 가격이 오르면 어떡하지"라는 망설임이 있는 사용자를 위한 흐름. 잠금이 그 망설임을 없애 방문을 두 번으로 늘린다.

```
오전장(06:00~15:59) 방문
  → 마음에 드는 빵의 오전가 확인, 오후 가격 변동이 걱정돼 구매를 망설임
  → "가격 잠금" 선택(하루 1회) → 오전가가 보장가로 고정됨
  → (이탈 — 오늘은 결제까지 가지 않음)
  → 16:00 오후장 재방문
  → 오후가 확인:
      오후가가 올랐으면 → 보장가와의 차액을 쿠폰으로 보전, 보장가로 구매
      오후가가 내렸으면 → 잠금 안 쓰고 더 싼 오후가로 구매
  → 자사몰 이동 → 구매 완료
```

### 흐름 ③ 오늘의 보상 고르기 — 안정형 즉시구매 vs 공격형 예측·재방문

같은 화면에서 두 갈래로 갈린다. "지금 바로 사고 싶은 사람"과 "위험을 감수하고 더 큰 혜택을 노리는 사람"을 분리해서, 즉시 전환과 재방문 유도를 동시에 만든다.

```
"오늘의 보상 고르기" 화면 진입 → 안정형 / 공격형 선택

[안정형 — 지금 바로 구매할 사람]
  → 선택 즉시 정해진 범위 내 랜덤 확정 쿠폰 지급
  → 자사몰 이동 → 바로 구매 완료

[공격형 — 하이리스크·하이리턴, 투자형 사용자]
  → 내일 가격이 오를지 내릴지 예측 참여
  → 안정형보다 훨씬 넓은 범위의 랜덤 할인율을 걸고 대기(익일 06:00 판정)
  → (이탈 — 오늘은 쿠폰 없음, 결과가 궁금해서 다음 날 재방문)
  → 익일 06:00 재방문 → 예측 결과 확인
  → 적중 시 폭넓은 범위의 쿠폰 수령 → 자사몰 이동 → 구매 완료
```

**세 흐름의 공통점과 차이**: 셋 다 마지막은 자사몰 구매로 수렴하지만, ①은 방문 1회로 끝나고 ②·③은 의도적으로 방문을 2회로 쪼갠다 — ②는 "망설임 해소"로, ③은 "결과가 궁금해서"로 재방문 동기를 만든다는 점이 다르다. 발표덱에서는 이 차이를 하나의 흐름도에 욱여넣지 말고 3개 패널(또는 3개 슬라이드)로 나눠 각각 완결된 스토리로 보여준다.
